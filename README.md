# 25학번 자봉 장부

치전원 25학번의 자봉(벌점)·상점을 기록하고, 학생 전원이 실시간으로 볼 수 있게 하는 웹앱이다.

- **학생**: 로그인 없이 링크로 자봉 현황(번호와 자봉 점수)을 보고, 자기 번호로 공결을 신청한다.
- **총대단** (총대, 실습부장 1·2, 운영부장, 총무, 학습부장, 정리부장, 치아부장): 자봉·상점을 요청한다. 총대와 실습부장 1·2는 출석을 체크해 **출석 요청**을 보낸다. 자기 비밀번호는 로그인 후 "비밀번호 바꾸기"로 직접 바꾼다.
- **부총대** (관리자 한 명): 출석 저장, 자봉 탭에서 자봉·상점 주기, 수정·무효 처리, 요청·출석 요청·공결 승인, 공지 문구, 엑셀 내보내기, 명단·비밀번호 관리, 작업 내역에서 뒤로가기·앞으로 가기.

자봉은 `+`, 상점은 `-`로 기록한다. 부총대가 **자봉 면제**로 지정한 학생(관리 탭)은 출석·기록·요청으로 들어오는 자봉이 쌓이지 않고 상점만 받는다. 면제 표시와 "자봉 많은 순" 정렬은 총대단 화면에만 있고, 학생 자봉 현황은 번호순만 보인다. 화면의 "자봉"은 둘을 합친 점수이고, 음수면 남은 상점이 이월된 것이다.
기록은 지우지 않는다. 수정하면 이력이 남고, 무효 처리하면 줄이 그어진 채로 남는다.
부총대가 기록·승인·출석 저장 등을 하면 안내 옆에 **되돌리기** 버튼이 몇 초 동안 뜬다 (작업 내역의 "이 작업만 되돌리기"와 같고, 작업 내역에서 다시 살릴 수 있다).
학생은 **리액션** 탭에서 수업 중 대답한 것(교시·질문·내 대답)을 **그날 안에, 하루 3번까지** 신청한다. 부총대가 요청함에서 승인한 리액션 3번마다 상점 1점("리액션 상점")이 자동으로 생기고, 남는 것은 다음으로 이월된다.
리액션 탭 아래에는 모든 학생의 리액션이 최신순으로 보인다(번호만, 30개씩 더 보기). 엑셀 내보내기에는 "리액션" 시트(날짜·번호·교시·질문·대답·결과)가 들어가고, 보관 후 정리를 하면 그 기간의 리액션 내역은 지워지고 학생별 이월 횟수와 받은 리액션 상점 수만 남는다. 엑셀로 정리하던 이월은 부총대가 **관리 → 리액션 이월 맞추기**에 "번호·이월 횟수(0~2)"를 붙여넣어 옮긴다.
공결 신청은 지각·결석 한 건씩, 또는 그날 두 건 이상이면 **하루 전체**로 한 번에 할 수 있다. 하루 전체 신청은 부총대에게 한 카드로 보이고 한 번에 승인·반려된다 (신청할 때 이미 기록된 그날의 지각·결석이 대상).
학생은 자봉 현황에서 **내 번호**를 정해 두면 그 폰에서 내 자봉·최근 기록을 맨 위에서 보고, 공결 신청에 번호가 미리 들어간다 (그 폰에만 기억).
폰 홈 화면에 추가하면 앱처럼 열린다 (안드로이드 크롬은 자봉 현황 맨 위 "홈 화면에 앱으로 추가" 버튼, 아이폰은 Safari 공유 → 홈 화면에 추가).
항목명·세부내용·교시·사유 칸을 누르면 최근·자주 쓴 값이 떠서 눌러 바로 넣을 수 있다 (항목명은 점수까지, 교시는 같은 요일 것을 먼저).
항목명 칸과 출석의 교시 추가 칸 오른쪽 **불러오기**로 직책마다 자주 쓰는 항목·교시를 저장해 두고 고른다.
**여러 시간 수업**: 교시를 추가한 뒤 교시 아래 "1시간~4시간" 버튼으로 수업 시간을 정한다(기본 1시간, 자주 쓰는 교시에 시간을 저장해 뒀으면 그 이름으로 추가할 때 그 시간으로). 지각은 누를 때마다 1점씩, 결석은 누를 때마다 한 시간(2점)씩 늘고, 시간을 넘으면 출석으로 돌아간다(3시간 수업이면 지각 1 → 2 → 3점, 결석 2 → 4 → 6점 → 출석). 저장한 뒤에도 바꿀 수 있고, 줄이면 새 시간을 넘는 지각·결석 점수가 줄어든다. 한 학생에게 지각과 결석을 함께 줄 수도 있다(3시간 수업에서 지각 한 번, 결석 두 번 → "지각 1 · 결석 2" = 지각 +1, 결석 +4 두 줄, 합은 수업 시간까지). 공지 문구에는 "[1-3교시 구강해부학 (3시간)]" 아래 "결석(+2)", "결석(+6)"처럼 점수별로 나뉘어 나온다. 자주 쓰는 교시에도 시간을 함께 저장한다.

출석 탭의 **지각 다시 부르기**: 지각이 한 명이라도 있으면 목록 맨 아래(저장 바로 위)에 지각인 학생만 번호순으로 저절로 모인다. 한 바퀴 부르고 내려오면 바로 다시 부르면 된다. 칸을 누르면 지각 ↔ 출석만 바뀌고, 여기서 출석으로 바꾼 학생도 저장 전까지 남아 잘못 누르면 되돌릴 수 있다. 결석·공결은 나오지 않는다.
출석 탭의 **이름 바꾸기**는 교시 이름의 오타 등을 고친다(그 교시로 준 자봉의 세부내용도 함께 바뀐다). 바꾸고 지울 수 있는 사람은 아래 삭제와 같다.
출석 탭의 **이 교시 삭제**: 부총대는 어느 교시든 지울 수 있고(그 교시로 준 자봉은 "교시 삭제"로 무효 처리되어 남는다), 출석을 체크하는 총대단은 아직 저장 안 된 교시만 지울 수 있다.

## 처음 설정 (한 번만, 20분 정도)

돈이 드는 단계는 없다. Supabase(데이터베이스)와 Vercel(웹사이트) 무료 요금제를 쓴다.

### 1. Supabase 프로젝트 만들기

1. <https://supabase.com> 에 GitHub 계정으로 가입한다.
2. **New project**를 누르고 아래처럼 만든다.
   - Name: `jabong`
   - Database Password: 아무거나 길게 정하고 따로 적어 둔다. 앱에서는 쓰지 않는다.
   - Region: **Northeast Asia (Seoul)**
3. 왼쪽 메뉴 **SQL Editor** → **New query**에 [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여넣고 **Run**을 누른다.
   - "Success. No rows returned"가 나오면 된다.
4. 다시 **New query**에 아래 한 줄을 넣고 **Run**을 누른다. 따옴표 안에는 처음 쓸 비밀번호를 넣는다.

   ```sql
   select init_app('처음비밀번호');
   ```

   - 모든 직책(부총대와 총대단 8명)의 비밀번호가 이것으로 정해진다. 나중에 앱에서 바꾼다.
   - 결과로 나오는 `ABCD-EFGH-JKLM` 모양의 **복구 코드**를 캡처해서 보관한다. 부총대가 비밀번호를 잊었을 때 쓴다.
5. 왼쪽 아래 **Project Settings** → **API Keys**(또는 **API**)에서 두 값을 복사해 둔다.
   - **Project URL**: `https://xxxx.supabase.co`
   - **anon public** 키 (또는 **Publishable key** `sb_publishable_...`). 공개돼도 괜찮은 키다. `service_role`/`secret` 키는 절대 쓰지 않는다.

### 2. Vercel에 올리기

1. <https://vercel.com> 에 GitHub 계정으로 가입한다.
2. **Add New… → Project**에서 `jabong` 저장소를 **Import**한다.
3. **Environment Variables**에 두 개를 넣는다.

   | Name | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | 위의 Project URL |
   | `VITE_SUPABASE_ANON_KEY` | 위의 anon(publishable) 키 |

4. **Deploy**를 누른다. 1분쯤 뒤 `https://jabong-xxxx.vercel.app` 같은 주소가 나온다. 이 주소를 카톡 공지방에 올리면 된다.
   - 저장소에 코드를 올리면(push) Vercel이 알아서 다시 배포한다.

### 3. 앱에서 마무리

1. 앱 주소 → **부총대** → 부총대로 로그인한다.
2. **관리 → 명단 붙여넣기**에 지금 쓰는 엑셀의 **번호·이름·자봉** 세 열을 복사해 붙여넣고 적용한다. 현재 자봉 점수가 "기존 누적"으로 들어간다.
3. **관리 → 비밀번호 → 다른 사람 비밀번호 재설정**으로 총대단 각자의 비밀번호를 새로 정해 알려준다. 내 비밀번호도 바꾼다.
4. **관리 → 자주 쓰는 항목**에서 항목과 점수를 확인한다.

### 4. 잠들지 않게 하기 (권장)

Supabase 무료 프로젝트는 **1주일 동안 아무도 접속하지 않으면 일시정지**된다. 방학 때 멈추지 않도록, 이 저장소의 GitHub Actions가 사흘마다 한 번 접속한다.

GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**으로 두 개를 넣는다.

| Name | Value |
|---|---|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon(publishable) 키 |

**Actions** 탭 → "잠들지 않게 깨우기" → **Run workflow**로 한 번 돌려서 초록불이 뜨는지 확인한다.
만약 멈췄다면 Supabase 대시보드에서 **Restore project**를 누르면 데이터 그대로 다시 켜진다.

### 5. 서버 반영 버튼 (권장)

서버(`supabase/schema.sql`)가 바뀌었을 때 SQL Editor에 붙여넣는 대신, GitHub의 버튼 하나로 반영한다. 폰 브라우저에서도 된다.

1. Supabase 대시보드 위쪽 **Connect** → **Session pooler**의 주소(`postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-…pooler.supabase.com:5432/postgres`)를 복사한다. Direct connection 주소는 GitHub에서 접속이 안 된다.
2. `[YOUR-PASSWORD]`를 데이터베이스 비밀번호로 바꾼다. 모르면 **Project Settings → Database → Reset database password**로 새로 정한다 (앱은 이 비밀번호를 쓰지 않아서 바꿔도 앱에는 영향이 없다).
3. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**: Name `SUPABASE_DB_URL`, Value에 2의 주소.

쓸 때: **Actions** 탭 → **서버 반영** → **Run workflow**. 그 버전의 테스트가 통과했을 때만 실행되고, 한 덩어리로 실행해서 중간에 실패하면 아무것도 바뀌지 않는다. 이 주소는 데이터베이스 비밀번호가 들어 있으니 Secrets 말고 다른 곳에 적지 않는다.

## 운영 메모

- **무료 한도**: 데이터베이스 500MB. 기록은 글자라 몇 년을 써도 수 MB다. 증빙 사진은 약 50~100KB로 줄여 저장하고, 처리 180일 뒤 자동으로 지운다.
- **백업**: [jabong-backup](https://github.com/Koderjoon/jabong-backup) 저장소의 GitHub Actions가 매일 새벽 3시에 전체 데이터를 `backups/날짜.json`으로 올린다 (암호화하지 않아 누구나 읽을 수 있다). 처음 설정과 되살리는 방법은 그 저장소의 README에 있다. 앱의 **관리 → 백업**에서 언제든 직접 파일을 받을 수도 있다. 매달 **공지 → 내보내기**로 만드는 엑셀은 사람이 읽는 용도이고, 백업 파일은 앱에 통째로 되살리는 용도다.
- **디데이** (관리 탭 → 디데이 링크): 디데이 사이트 주소를 보기 키(`#k=…`)까지 붙여넣으면 학생 화면의 첫 탭이 "디데이"가 되고, 그 사이트와 같은 마감 목록(오늘·내일·7일 이내·그 이후, D-day)이 보인다. 마지막으로 받은 목록은 폰에 기억해 두어 인터넷이 끊겨도 보인다. 비우면 탭이 사라진다.
- **디데이 관리** (관리 탭 → 디데이 관리자 링크): 관리자 키(`#k=…`)가 든 주소를 넣으면 로그인한 총대단·부총대 화면의 첫 탭이 "디데이"가 되고, 거기서 바로 일정을 추가(제목·날짜·시각·분류·세부)·수정·삭제할 수 있다. 고친 일정은 디데이 사이트와 학생 화면에도 반영된다. 이 링크는 학생 화면과 백업 파일에는 들어가지 않는다.
- **학급 매점 링크** (관리 탭): 링크를 넣으면 모든 화면(학생·총대단·부총대)의 자봉 현황 맨 위에 "학급 매점 열기" 버튼이 생기고, 누르면 새 창(폰은 구글 시트 앱)으로 열린다. `https://` 주소만 받고, 비우고 저장하면 버튼이 사라진다. 구글 시트 공유는 "링크가 있는 모든 사용자 → 뷰어"로 둔다.
- **보관 후 정리** (관리 탭): 기준 날짜까지의 기록을 학생별 "이월" 한 줄로 합친다. 점수는 그대로다. 먼저 전체 기간 엑셀을 받아야 버튼이 켜진다(받은 뒤 장부가 바뀌면 다시 받아야 한다). 보통 1년에 한 번이면 충분하다.
- **작업 내역**: 누가 언제 무엇을 바꿨는지 남는다. 부총대는 **뒤로가기·앞으로 가기**로 작업 단위로 오가고, "이 시점으로"로 특정 작업 직후로 바로 가거나, "이 작업만 되돌리기"로 작업 하나를 빼 둘 수 있다 (빼 둔 작업은 "다시 살리기"로 되살린다). 이동·되돌리기는 기록으로 남지 않는다. 뒤로 간 상태에서 누가 새 작업을 하면(학생의 신청 포함) 앞으로 갈 수 있던 작업은 사라지므로, 뒤로 간 동안은 맨 위에 경고와 "맨 끝으로 돌아가기" 버튼이 뜬다. 한 번에 옮길 수 있는 작업은 1,500개까지다(넘으면 가까운 시점으로 나눠서 옮긴다). 이동 전에 바뀌는 점수·번호를 미리 보여 준다. 보관 후 정리와 백업에서 되살리기 너머로는 갈 수 없다.
- **인수인계**: 다음 부총대에게 비밀번호와 복구 코드를 넘기고, 받은 사람이 로그인해서 자기 비밀번호로 바꾼다. Supabase·Vercel 프로젝트도 넘겨야 하면 각 서비스의 팀 초대 또는 프로젝트 이전 기능을 쓴다.
- **비밀번호를 잊었을 때**: 총대단은 부총대가 재설정한다. 부총대는 로그인 화면의 "복구 코드로 들어가기".
- 비밀번호를 5번 틀리면 그 직책은 10분 동안 잠긴다.

## 개발

```bash
npm install
cp .env.example .env.local   # Supabase 주소와 키를 넣는다
npm run dev                  # http://localhost:5173
npm run build
```

테스트는 세 가지다. CI(GitHub Actions)가 올릴 때마다 모두 돌린다.

| 명령 | 무엇을 | 필요한 것 |
|---|---|---|
| `npm test` | 계산 로직 (공지 문구, 명단 붙여넣기, 내보내기) | 없음 |
| `npm run test:db` | 모든 서버 함수: 권한·입력 검사·동작, 작업 내역 이동·되돌리기, 백업·정리 | Postgres 16 |
| `npm run test:e2e` | 실제 화면을 Chromium으로 열고 학생·총대단·부총대의 모든 버튼을 누른다. 동시에 들어오는 요청(로그인 잠금, 같은 교시 추가)도 | Postgres 16, Chromium |

```bash
# Postgres 접속 정보 (예시)
export PGHOST=localhost PGUSER=postgres PGPASSWORD=postgres
npm run test:db
npx playwright install chromium   # 처음 한 번
npm run test:e2e
```

- DB 테스트(`supabase/tests/`)는 테스트마다 새 DB를 만들고 `schema.sql`을 두 번 실행한 뒤 돌린다. 함수는 브라우저와 같은 `anon` 역할로 부른다.
  - `flow.sql`: 처음부터 끝까지 한 번 쓰는 흐름
  - `functions.sql`: 서버 함수 40개 전부 (노출·권한, 입력 검사 문구, 동작, 로그인 잠금, 복구 코드, 사진 정리, 백업·정리)
  - `scale.sql`: 한 학기 분량(학생 70명, 작업 약 800개)에서 맨 처음 ↔ 맨 끝 이동이 3초 안에
  - `rewind.sql`, `rewind_all.sql`: 뒤로가기·앞으로 가기·이 작업만 되돌리기. 데이터를 바꾸는 모든 함수를 부른 뒤 모든 시점으로 오가며 데이터가 그 시점과 똑같은지 확인한다
- 브라우저 테스트(`e2e/`)는 가짜 Supabase(`e2e/server.mjs`, 로컬 Postgres 함수를 부른다)로 인터넷 없이 돈다. 폰 크기(390px, 320px) 화면이 가로로 넘치지 않는지와 화면 오류가 없는지도 본다. Realtime(다른 기기의 변경이 바로 보이는 것)은 흉내 내지 않는다. 시스템에 따로 설치된 Chromium을 쓰려면 `CHROMIUM_PATH`에 실행 파일 경로를 준다.

`schema.sql`은 여러 번 실행해도 된다. 함수를 고쳤으면 Supabase SQL Editor에 파일 전체를 다시 붙여넣고 실행한다.
